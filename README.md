# candidate-generation-avito

Решение задачи первого этапа поиска (Retrieval) для отбора топ-50 релевантных объявлений по поисковому запросу пользователя. Результат на тестовых данных (Recall@50): ~0.75.

Основной пайплайн: [main_pipeline.ipynb](main_pipeline.ipynb)

Educational Data Analysis: [eda.ipynb](eda.ipynb)

## 1. Данные и используемые признаки

В ходе разведочного анализа (EDA) корпуса benchmark_items и исторических кликов
train были отобраны следующие признаки:

Признаки запроса:
- search_query: основа лексического и семантического поиска.
- search_infm_params_text: очищен от системного мусора, извлечены значения фильтров и минимальный требуемый рейтинг (используется как жесткий фильтр).
- search_category: используется как жесткий фильтр (совпадение в train составляет 99.9%).
- search_location_id: используется для мягкого бустинга. Совпадение локаций в train ~83%.

Признаки объявлений:
- item_title_raw: имеет наибольший вес при поиске.
- item_infm_params_text + item_description_raw: склеены и обрезаны до 500 символов. Описание часто содержит спам, поэтому тексты обрезаются для снижения информационного шума при поиске.
- item_rating, item_rating_reviews_count, item_is_phone_hidden, item_is_message_forbidden. Применяются в виде корректирующих множителей к скорам (score). Коэффициенты подбирались эмпирически.

Отброшенные признаки:
- item_price: имеет выбросы и часто означает цену по договорённости (значения 0 и меньше). На этапе кандидатогенерации вносит шум.
- search_is_delivery_search, item_latitude, item_longitude: неинформативны в рамках доступных данных.

Более подробный анализ находится в eda.ipynb.

## 2. Архитектура решения

Пайплайн построен по принципу Гибридного поиска (Hybrid Search) без использования тяжелых ранжирующих моделей, так как задача требует максимизации полноты (Recall), а не точности ранжирования (NDCG).

1. **Лексический поиск (BM25Okapi):** Построен на двух независимых индексах (Заголовки и Описания) с применением лемматизации (Pymorphy3). Хорошо справляется с точными совпадениями брендов и запросов.
2. **Семантический поиск (Bi-Encoder):** Использована модель intfloat/multilingual-e5-base. Тексты формируются с обязательными префиксами query: и passage:. Отвечает за понимание синонимов и ошибок в написании.
3. **Слияние шкал:** Нормализация методом min-max.
4. **Бизнес-эвристики:** Внедрены математические множители на итоговый скор:
- Рейтинг: Работает как коэффициент доверия (score * rating / 5.0).
- Количество отзывов: Прибавляется бонус по формуле x / (x + median), чтобы давать плавный буст проверенным мастерам, но ограничивать влияние накрученных отзывов.
- Локация и связь: Добавлены эмпирические множители (буст за совпадение города и штраф -10% за отсутствие телефона и запрет сообщений).

## 3. Локальная валидация

Для экономии попыток на платформе была настроена локальная валидация, имитирующая тест:
- «Мёртвые» объявления: из обучающей выборки train.parquet я оставил для валидации только те объявления, где item_id физически присутствует в поисковом индексе benchmark_items.parquet (33 010 строк из 497к).
- Группировка: Данные были сгруппированы по уникальным запросам, из которых случайным образом (с фиксированным random_state) выделено несколько тысяч запросов (1500 в основном пайплайне).
- Метрика: функция Recall@50 через пересечение множеств set.

## 4. Анализ ошибок и принятые решения

1.  Системный мусор в запросах:
- Проблема: Строка search_infm_params_text содержала технические теги, например "Вид услуги", "Тип услуги", которые воспринимались как часть поискового запроса.
- Решение: Написан Regex-парсер, удаляющий ключи и системные паттерны, оставляя только чистые значения фильтров (например, "автосервис", "обучение").
2. Пустая выдача из-за жестких фильтров:
- Проблема: Запросы с редкими категориями или высоким порогом рейтинга приводили к пустой выдаче объявлений.
- Решение: Внедрена логика многоступенчатого Fallback. Если по жестким фильтрам ничего не найдено, алгоритм последовательно отключает фильтр рейтинга, а затем и фильтр категории, производя поиск по всей базе. Модель никогда не возвращает пустой ответ.
3. Несовместимость шкал BM25 и нейросети:
- Проблема: Алгоритм BM25 выдает неограниченные скоры (score), в то время как косинусное сходство эмбеддингов E5 находится в строгих границах. Сложение скоров привело бы к тому, что BM25 полностью заглушил семантику нейросети.
- Решение: Min-Max нормализация. Скоры приводятся к единому диапазону [0, 1] строго внутри отфильтрованного подмножества кандидатов. Это позволило балансировать вес лексического и семантического поиска.

## 5. Воспроизводимость и запуск

Пайплайн написан с соблюдением принципа идемпотентности. При повторном запуске
код выдает идентичный answer.csv.

Запуск пайплайна:
1. Установите зависимости: pip install -r requirements.txt
2. Убедитесь, что файлы данных лежат в папке data/.
3. Убедитесь, что в .env указан HF_TOKEN (необязательно, но это ускорит загрузку модели).
4. Запустите ноутбук пайплайна: main_pipeline.ipynb.
5. Примечание: При первом запуске скрипт автоматически создаст папку cache/, выполнит векторизацию и токенизацию, сохранив индексы .pkl и .npy на диск. Все последующие запуски будут использовать кэш и инициализироваться за пару секунд.
